# Model Selection and AI Avatar Pipeline Decisions

The week’s work clarified that the gpt‑oss:120b model delivers reliable structured‑JSON output and lower latency than Nemotron‑120b, and it defined a concrete, low‑effort launch path for an AI avatar using VRoid‑generated VRM and AITuberKit while keeping ARDY‑based full‑body motion as an optional differentiation layer.

## GPT‑OSS vs Nemotron: Structured‑JSON Performance  
The comparison ran on a GB10 system with 121 GB unified memory, using temperature = 0.1 and `max_tokens=4096` for all JSON‑producing tasks. Four production tasks were measured: URL classification, audit judgment, article summarization, and work‑log summarization. gpt‑oss:120b produced zero empty responses, no errors, and schema‑compliant JSON across all tasks, with runtimes ranging from 20 s to 138 s. Nemotron‑120b exhibited empty‑response incidents in 2/8 article summaries and 0/5 work‑log summaries, incurred two HTTP 400 context‑length errors, and ran 2–4 × slower (up to 480 s). The token budget was consumed by reasoning, leaving no content field for long prompts. The implication is that gpt‑oss should remain the default operational model, while Nemotron is reserved for specialist calls that can afford larger `max_tokens` (8 k–16 k+) and tolerate higher latency.

## Avatar Creation Roadmap: Skeleton Mapping and VRM Generation  
The roadmap begins with a character specification lacking a VRM and adopts NVIDIA ARDY for text‑to‑motion generation. Phase 0 evaluates three display runtimes—A) existing VTuber apps (VSeeFace, VirtualMotionCapture), B) Three.js overlay, C) Unity + UniVRM—and recommends starting with option A to limit custom code to the retarget bridge. Phase 1 creates the VRM: (a) 2D illustration → VRoid Studio export, (b) existing 3D model → UniVRM or Blender add‑on export, (c) outsourced model → Unity Humanoid‑rig compliant VRM. Phase 2 installs ARDY on Ubuntu 22.04 with RTX GPU, CUDA‑compatible PyTorch ≥ 2.4, and the Meta‑Llama‑3‑8B‑Instruct encoder, targeting ≈ 20 fps generation. Phase 3 builds a mapping table from ARDY Core joint names to VRM Humanoid bones, resolves axis differences, and validates motion conversion offline before live streaming. Phase 4 integrates YouTube Live comment polling, voice synthesis, and OBS output, completing an end‑to‑end comment‑driven stream.

## Quick‑Start Stack: AITuberKit, Claude, and OBS Integration  
The quick‑start adopts the “balance / fastest” preset, omitting ARDY and using a 3D VRM produced in VRoid Studio. AITuberKit (Pixiv‑forked ChatVRM) provides VRM rendering, motion‑tag gestures, lip‑sync, YouTube comment ingestion, and idle speaking within a single web app. Claude (Anthropic) serves as the default LLM, with interchangeable support for OpenAI, Gemini, Groq, Mistral, DeepSeek, or OpenRouter. TTS is configured via VOICEVOX or ElevenLabs, and the video feed is composited in OBS Studio via a browser source. Licensing notes specify that AITuberKit v2.0.0 is free for personal, educational, or non‑profit use, but commercial streams require a separate license; VRM, TTS, and LLM providers also demand commercial compliance checks. The implication is that a functional streaming pipeline can be launched in a single day, with modular replacement points for higher‑quality facial animation (Audio2Face) or full‑body motion (ARDY) later.

## Technology Options Matrix: Creation, Animation, Conversation, Streaming  
The four‑step pipeline is mapped to alternative tools. Creation options range from free VRoid Studio (anime‑style VRM) to paid solutions such as MetaHuman or outsourced modeling, with the decision axis of art style versus cost. Animation choices include human‑performed capture (VSeeFace, iFacialMocap) and AI‑generated motion (ARDY, DeepMotion, Mixamo); ARDY is highlighted as high‑differentiation but high‑risk. Conversation can be built on integrated frameworks (AITuberKit supporting multiple LLMs and TTS) or commercial platforms (NVIDIA ACE, Convai, Inworld). Streaming uniformly relies on OBS Studio, with runtimes such as VSeeFace, VMagicMirror, or custom Unity/Three.js layers. Preset combinations are defined: fastest launch (VRoid + VMagicMirror + AITuberKit + OBS), balanced (VRoid + Audio2Face + AITuberKit + OBS), and full‑body AI (custom VRM + ARDY + custom stack). The key finding is that the balanced preset satisfies immediate production needs while preserving a path to incorporate ARDY for future differentiation.

**Synthesis** – The empirical superiority of gpt‑oss for structured‑JSON tasks justifies its continued use as the core LLM, and the articulated avatar pipeline demonstrates that a production‑ready AI VTuber can be launched rapidly with VRoid and AITuberKit, reserving ARDY‑based full‑body motion for later stages where differentiation outweighs integration risk. Subsequent work will focus on validating the ARDY retarget bridge at scale and measuring the impact of higher‑cost creation or animation options on deployment timelines.
